# Organizations own Projects, not Users

Planning the Org feature (TBR-10), we chose to make every Project owned by an Organization — with an Organization auto-created per User on signup — rather than letting Organizations exist alongside personal, directly user-owned Projects. The alternative (personal Projects and Org-owned Projects as two parallel kinds) was rejected because it would leave two permanent authorization code paths in `src/features/projects/api.ts` (direct `userId` equality vs. Membership/Grant checks) instead of one. This means `projects.userId` is retired entirely once the feature ships — every Project, including a user's private ones, resolves access through an Organization Membership and, for non-admins, a per-Project Grant (see `CONTEXT.md`: Organization, Membership, Role, Grant).
